# M1 — Движение и мир

> Перед стартом: `docs/prompts/00_session_start.md`. Опирается на M0.

## Цель
Игрок управляет чиби-героем в тайловой комнате на телефоне: плавно, отзывчиво, со стабильной камерой.
Заложить ECS-lite, игровой цикл и границу core↔render, которые дальше не переписываются.

## Контекст
GDD §4.1, §6; ARCHITECTURE §5, §6, §7; STORY §2 (внешность Тави).

## Задачи
1. **ECS-lite** (`core/ecs`): `World` (create/destroy entity, add/get/remove component, `query(...components)`
   с кэшем), компоненты — plain data: `Transform2D {x,y,rot}`, `Velocity`, `Collider {radius}`, `PlayerControlled`,
   `MoveStats {speed, accel, decel}`. Тесты.
2. **GameLoop** (`app/GameLoop.ts`): фиксированный шаг 30 Гц, аккумулятор, clamp больших dt (после сворачивания
   вкладки ≤ 0.25 с), `alpha` для интерполяции; пауза по `visibilitychange`.
3. **Команды ввода**: `platform/input` → абстрактный `InputState {move: vec2 (|v|≤1), buttons}`; в core попадает
   только `InputState`, не события DOM.
4. **Виртуальный джойстик** (Preact, `ui/joystick`): плавающий (появляется под пальцем в левой половине),
   dead-zone 10%, мультитач (второй палец — правая половина — не сбивает джойстик). Клавиатура WASD как dev-фолбэк.
5. **Движение** (`core/systems/movement.ts`): ускорение/торможение, поворот к направлению движения с ограничением
   угловой скорости.
6. **Тайловая карта** (`core/dungeon/TileMap`): сетка (пол/стена/пустота), `content/rooms/test_room.ts`
   (ASCII-шаблон `#`, `.`), коллизия круг-против-тайлов со скольжением вдоль стен. Тесты углов и узких проходов.
7. **Рендер комнаты**: `InstancedMesh` для пола и стен, toon-материал, стены с outline, лёгкий декор
   (грибы-светлячки — emissive), тени — запечённые/фейковые blob-тени (без shadow map на low).
8. **Чиби-герой** (`render/models/chibi.ts`): процедурная сборка по параметрам (цвет волос/одежды, причёска
   из примитивов: чёлка, хвостик), большие глаза — текстура на CanvasTexture. Idle-покачивание и анимация шага
   (процедурная: подпрыгивание, наклон). Параметры Тави — из `content/characters/tavi.ts`.
9. **Камера**: изометрическая сверху-сзади (~50°), сглаженное следование, look-ahead по направлению движения,
   не проходит сквозь стены (ограничение по bounds комнаты).
10. **Синхронизация render↔core**: `render/EntityViews` — map entity→Object3D, интерполяция между prev/curr
    Transform по `alpha`; создание/удаление вью по событиям `EntitySpawned/Despawned`.
11. **E2E**: Playwright — тач-драг в левой половине (у Playwright нет API драга пальцем: CDP
    `Input.dispatchTouchEvent` через `page.context().newCDPSession(page)` или синтетические `PointerEvent` с
    `pointerType: 'touch'`; джойстик реализовать на Pointer Events) → позиция героя (через `window.__debug.getPlayerPos()`, только
    в dev/test сборке) изменилась; герой не проходит сквозь стену.

## DoD
- [ ] Движение отзывчиво на телефоне (задержка ввода ≤ 1 кадра симуляции), без дрожания камеры.
- [ ] Коллизии без застреваний в углах (тесты + ручная проверка).
- [ ] ≥ 55 FPS на десктопе в мобильном вьюпорте, draw calls ≤ 30 для комнаты.
- [ ] **Проверка на реальном телефоне** — попросить пользователя открыть сборку и сообщить FPS из `?debug=1`;
      записать в STATUS (риск R1).
- [ ] Unit + e2e зелёные, ревью APPROVE, документация, тег `v0.1.0`.

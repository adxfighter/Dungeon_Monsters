# M3 — Добыча и разделка

> Перед стартом: `docs/prompts/00_session_start.md`. Опирается на M2.

## Цель
Каждый убитый монстр превращается в ингредиенты, качество которых зависит от способа убийства и мини-игры разделки.

## Контекст
GDD §4.3 (элемент → качество), §4.4, §4.7.

## Задачи
1. **Схемы**: `IngredientDef {id, nameKey, tags[] (meat, veg, fungus, liquid, spice, bone, jelly...), baseQuality,
   flavor {savory, sweet, sour, bitter, spicy}, perishable?, iconKey}`; `MonsterDef.drops` → `{partId,
   ingredientId, count, cutLine}`; правила модификации качества от `killElement`/overkill в `content/balance.ts`.
2. **15 ингредиентов** Яруса I (из 3 монстров M2 + 5 растений/грибов, собираемых в комнатах как интерактивные объекты).
3. **Система loot** (core): на `MonsterKilled` → туша-объект с таймером; взаимодействие → старт разделки.
4. **Мини-игра разделки** (UI + core-оценка): 2–4 пунктирные линии поверх крупного плана монстра; оценка
   точности свайпа (отклонение от кривой, скорость) → ★1–★3; кнопка «Пропустить» (★1). Опция доступности
   «упрощённая» (тап по точкам). Оценка — чистая функция в core с тестами.
5. **Рюкзак**: лимит по весу/слотам (данные), стаки по `ingredientId+quality`, выбросить; UI-экран рюкзака.
6. **Сбор растений**: интерактивные объекты в комнате (кнопка «Действие» появляется рядом).
7. **Бестиарий v1**: запись открывается при первой встрече, дополняется при разделке (съедобные части,
   лучший способ убийства). UI-книга с кремовой бумагой.
8. **Тесты**: формулы качества, стаки, лимиты рюкзака, целостность ссылок монстр→ингредиент.

## DoD
- [ ] Цикл «убил → разделал → в рюкзаке» работает на телефоне, мини-игра приятна и укладывается в 2–4 с.
- [ ] Убийство огнём vs мечом даёт разное качество (тест + визуально).
- [ ] Бестиарий показывает 3 монстра. Ревью APPROVE, документы, тег `v0.3.0`.

# ADR-0001: Веб-стек TypeScript + Three.js вместо Unity/Godot

- Статус: **Принято**
- Дата: 2026-09-28
- Автор: CTO (Claude)

## Контекст
Игру реализует ИИ-агент (Claude Opus 5.5) в Claude Code на Windows. Агенту нужно самостоятельно собирать,
запускать, тестировать и **видеть** результат. Цель — мобильная 3D-игра с аниме-стилем.

## Рассмотренные варианты
| Вариант | + | − |
|---|---|---|
| Unity (C#) | индустриальный стандарт, ассет-стор, нативная производительность | сцены/префабы — бинарно-YAML, редактор GUI; агент не может запустить и увидеть игру; лицензирование |
| Godot 4 | открытый, текстовые сцены (.tscn), CLI | мобильный экспорт и отладка сложнее для агента; меньше примеров; визуальная проверка затруднена |
| **Three.js + TS** | всё — текст и код; dev-сервер + браузер-превью + Playwright дают агенту полный цикл «код → запуск → скриншот → тест»; PWA и Capacitor для сторов | производительность WebGL ниже нативной; нужно самим писать toon-шейдинг, ECS, инструменты |
| Babylon.js | больше встроенного (физика, инспектор) | тяжелее бандл, меньше гибкости |

## Решение
TypeScript + Vite + Three.js, UI на Preact, упаковка Capacitor. Строгий бюджет производительности
и стилизованная low-poly графика компенсируют разрыв с нативом.

## Последствия
- Нужны собственные: ECS-lite, toon-материал, outline, простая коллизия.
- Все проверки автоматизируемы → высокая автономность агента.
- Пересмотр при провале perf-бюджета на реальном устройстве в M1/M5 (триггер: < 30 FPS на mid-range после оптимизаций).

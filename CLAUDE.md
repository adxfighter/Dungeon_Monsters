# Dungeon Monsters — правила для Claude (читать в начале КАЖДОЙ сессии)

Мобильная 3D-игра в аниме-стиле (cel-shading) про экспедицию в живое подземелье,
где монстров побеждают, разделывают и готовят. Вдохновлена Dungeon Meshi, но это
**оригинальная IP** (см. `docs/LEGAL.md`).

## 0. Старт сессии (обязательно, по порядку)
1. Прочитать `docs/STATUS.md` — где мы остановились, текущий milestone, открытые задачи.
2. Прочитать `docs/ROADMAP.md` (раздел текущего milestone) и соответствующий промт в `docs/prompts/milestones/`.
3. Просмотреть свежие ADR в `docs/adr/` и `docs/DECISIONS_LOG.md`.
4. `git status`, `git log --oneline -10`, `git branch -a --no-merged main` — убедиться, что дерево чистое;
   если есть незамёрженная ветка `m*/` — актуальный `STATUS.md` может быть в ней, прочитать оттуда.
Не начинать кодить, не выполнив эти шаги. Шаблон старта: `docs/prompts/00_session_start.md`.

## 1. Язык
- Документация, коммиты (тело), общение с пользователем — **по-русски**.
- Код, идентификаторы, имена файлов, ключи локализации — **по-английски**.
- Заголовок коммита — Conventional Commits на английском: `feat(combat): add dodge roll`.

## 2. Стек (зафиксирован ADR-0001, менять только новым ADR)
TypeScript (strict) · Vite · Three.js · Preact (UI-оверлей) · Vitest · Playwright · ESLint + Prettier ·
Zod (валидация данных) · IndexedDB (сохранения) · Capacitor (Android/iOS на этапе релиза).

## 3. Архитектурные инварианты (см. `docs/ARCHITECTURE.md`)
- `src/core/**` — чистая игровая логика. **Запрещено** импортировать `three`, `preact`, DOM, `window`,
  `Math.random` (только `core/rng`), `Date.now` (только через `Clock`). Детерминированность и тесты.
- `src/render/**` читает состояние core и рисует; **не меняет** игровое состояние напрямую.
- `src/ui/**` общается с core только через команды (`dispatch(Command)`) и селекторы.
- Контент (монстры, ингредиенты, рецепты, этажи, диалоги) — данные в `src/content/**`, валидируются Zod-схемами.
  Никаких магических чисел баланса в коде систем.
- Все тексты игрока — через i18n-ключи (`ru` основной, `en` второй).
- Сохранения версионируются (`saveVersion`) и имеют миграции.

## 4. Процесс разработки
- Работа ведётся **по milestone** из `docs/ROADMAP.md`. Одна задача = одна ветка `m<N>/<short-name>` = один PR.
- Не расширять объём задачи молча. Найденное вне задачи → в `docs/STATUS.md` раздел «Бэклог».
- Каждая фича: код + тесты core (Vitest) + обновление документации в том же PR.
- Перед коммитом обязательно зелёные: `npm run typecheck && npm run lint && npm run test && npm run build`.
- Визуальные изменения проверять в браузере в мобильном вьюпорте 390×844 и делать скриншот: в десктоп-приложении —
  встроенный браузер (`preview_start` с конфигом `.claude/launch.json`); в CLI — `npm run screenshot`
  (Playwright, сохраняет PNG в `test-results/screens/`).
- `npm create vite` и любые генераторы — **только во временном каталоге**, затем перенос файлов; никогда
  `--overwrite` в корне (удалит документацию).
- Бюджет производительности — единственный источник `docs/ARCHITECTURE.md` §10 (кратко: 60/30 FPS,
  ≤ 150 draw calls, ≤ 150k tris, стартовый JS ≤ 1 МБ gzip, весь стартовый бандл ≤ 3 МБ).
- WIP-исключение: коммит `docs:`/`wip:` в ветке задачи в конце сессии допускается без полного набора проверок,
  если задача не закончена (в `main` — никогда).
- Не коммитить секреты, ключи, `.env`. Не пушить `--force` в `main`.
- В `main` — только через PR после независимого ревью (см. §5). Merge — squash.

## 5. Независимое ревью (обязательно перед merge)
После реализации задачи запустить субагента `reviewer` (`.claude/agents/reviewer.md`) с промтом
`docs/prompts/10_independent_review.md`. Ревьюер НЕ видит рассуждений автора — только diff, задачу и документы.
Все findings уровня **blocker/major** исправить или письменно обосновать в PR, затем **повторно** запустить
`reviewer` на обновлённый diff (до вердикта APPROVE). Итог ревью — в описание PR.

## 6. Документация (обязательно в конце каждой задачи/сессии)
Запустить субагента `doc-keeper` (`.claude/agents/doc-keeper.md`) с промтом `docs/prompts/20_docs_update.md`, либо
выполнить промт самому. Минимум:
- `docs/STATUS.md` — что сделано, что дальше, блокеры (дата абсолютная, YYYY-MM-DD).
- `docs/DECISIONS_LOG.md` — короткая запись о каждом нетривиальном решении; крупное → новый ADR в `docs/adr/`.
- `docs/CHANGELOG.md` — пользовательские изменения.
- Если изменились GDD/архитектура/контент — обновить соответствующий документ.

## 7. Ассеты и IP
- Только собственные/процедурные ассеты или CC0/CC-BY с записью в `docs/ASSETS.md` (источник, лицензия, автор).
- Запрещено использовать имена, персонажей, арты, сюжет, названия из Dungeon Meshi (Laios, Marcille, Chilchuck,
  Senshi, Falin, «Golden Kingdom» и т. п.), узнаваемых монстров/блюд тайтла и ролевую динамику его отряда —
  полный список в `docs/LEGAL.md`. Монстров придумываем своих. Проверка — пункт чек-листа ревью.

## 8. Карта документов
`docs/README.md` — индекс. Главное: `GDD.md`, `STORY.md`, `ARCHITECTURE.md`, `ROADMAP.md`, `STATUS.md`,
`LEGAL.md`, `ASSETS.md`, `adr/`, `prompts/`.
